[R27] 编写新的功能代码前，必须先检索 GitHub 上成熟开源项目的同类实现（用 WebSearch/WebFetch 搜"<功能> STM32/<库> example"，重点看官方仓库与高星项目），对照至少 1~2 个参考实现后再动手；参考到的关键做法（数据结构、流程、坑）在代码注释或 FEAT 文档中注明出处链接。纯 CubeMX 模板类机械改动（改引脚/加外设初始化）可豁免。项目内已有可复用模式（如 i2s_drv 回调架构、A2-01 的 vendored 集成模式）时，复用优先于外部检索。

[R28] 从 GitHub 抄成熟代码时，必须先核对**硬件一致性**，按层分类决定抄什么：
   - ✅ 可直接照抄（硬件无关）：协议帧格式、调用流程、数据结构、架构分层（如 4ilo 的 HAL_I2C_Mem_Write 0x00/0x40 寄存器模式）。
   - ❌ 禁止照抄（硬件强相关）：**电气参数/时序调优值**——SSD1306 的 0xD5 振荡/0xD9 预充电/0xDB VCOMH/0x81 对比度、上拉/驱动强度、时钟树配置等，是原作者对其具体模块/芯片的调优值而非标准值，**跨硬件不可移植**。此类值必须采用与本硬件实测跑通的来源（优先级：本块硬件实测过的工程 > 器件数据手册推荐值 > 开源默认值），并在代码注释注明来源与差异。
   - 优先检索顺序：与本硬件同型号同封装且实测跑通的项目 > 官方仓库 > 高星通用库（案例：OLED 排查走了 4 轮弯路——4ilo 参数、自拼帧、参数再换全错层，真根因是 BUG-20260829-006 的调度器时序；参数照搬是其中两轮弯路的直接推手）。
