1. **源码内部行为**：调库前必读被调函数源码——官方函数可能有隐藏副作用（A3-02 实证：`arm_mfcc_f32` 自带归一化+加窗，对已加窗帧整体调用即"窗叠窗"静默数值错）；
2. **Issue 区**：官方/参考仓库的 Issues（搜关键词 + 已关标签）是踩坑富矿——API 误用、边界条件、版本坑往往不在 README 里（用 `github.com/<repo>/issues?q=<关键词>` WebFetch）；
3. **坑清单交付物**：预研结论必须含"坑与预防"表（坑→后果→预防→验证判据），并入设计汇总防御设计节——没有坑清单的预研视为未完成。
   纯 CubeMX 模板类机械改动（改引脚/加外设初始化）可豁免。项目内已有可复用模式（如 i2s\_drv 回调架构、A2-01 的 vendored 集成模式）时，复用优先于外部检索。

\[MUST]\[R28] 从 GitHub 抄成熟代码时，必须先核对**硬件一致性**，按层分类决定抄什么：

* ✅ 可直接照抄（硬件无关）：协议帧格式、调用流程、数据结构、架构分层（如 4ilo 的 HAL\_I2C\_Mem\_Write 0x00/0x40 寄存器模式）。

* ❌ 禁止照抄（硬件强相关）：**电气参数/时序调优值**——SSD1306 的 0xD5 振荡/0xD9 预充电/0xDB VCOMH/0x81 对比度、上拉/驱动强度、时钟树配置等，是原作者对其具体模块/芯片的调优值而非标准值，**跨硬件不可移植**。此类值必须采用与本硬件实测跑通的来源（优先级：本块硬件实测过的工程 > 器件数据手册推荐值 > 开源默认值），并在代码注释注明来源与差异。

## §5 快速路径（机械改动豁免，防止"改个宏也要等确认"）

适用：改引脚号/波特率/宏定义值/纯注释/Makefile 加一行登记——**不涉及逻辑变更**。
豁免：R9 全量影响地图、R27 GitHub 调研。
必做：R20 引脚一致性（涉及时）+ 编译验证（R21 证据）+ 一句话影响说明（改了什么、为什么无连锁）。
不适用：任何触及 ISR/任务调度/数据流/串口字符串契约/初始化顺序的改动——这些走完整 R9 流程（A2 教训：一行 printf 搬家破坏契约、初始化重排修黑屏）。
**与 R19 的关系（冲突消解）**：CubeMX 生成代码（i2c.c/usart.c 级别）的引脚/波特率修改，走 §5 快速路径豁免 R9 全量地图，但必须在 hal\_msp.c 中交叉验证引脚一致性（R20），并在提交说明中登记"生成代码调整（§5 快速路径）"。
