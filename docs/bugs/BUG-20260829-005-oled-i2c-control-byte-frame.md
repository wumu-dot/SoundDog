# OLED I2C 手拼控制字节帧违反 SSD1306 手册 8.1.5.2——显存数据被当命令执行

- **Bug ID**：BUG-20260829-005
- **严重等级**：P1-重要（静默失败：I2C 层零报错但屏幕乱码）
- **发现日期**：2026-08-29
- **修复日期**：2026-08-29（代码修复；上板功能验证被 BUG-006 阻塞，待复核）
- **关联 FEAT**：FEAT-A2-03（OLED 频谱显示）

## 现象描述
自写 OLED 驱动把命令/数据拼进一次 `HAL_I2C_Master_Transmit`，控制字节序列不符合 SSD1306 手册 8.1.5.2 的 Co 位规则，芯片把显存数据字节当命令解析 → 屏幕乱码/异常条纹，而 HAL_I2C 返回 HAL_OK（**总线层完全无错，纯语义层静默失败**）。

## 复现步骤
1. 手拼帧：[START][0x78][控制字节][cmd...][数据...] 单笔 Master_Transmit
2. 烧录后屏显乱码，串口无任何 I2C 错误

## 根因分析
SSD1306 I2C 帧中控制字节（Co/D/C 位）决定后续字节是命令还是显存数据；自拼帧时控制字节序列违反手册规则。属于"没抄成熟实现、自行合并帧格式"引入的语义错误——I2C 协议正确 ≠ SSD1306 帧语义正确。

## 修复方案
照抄 4ilo/ssd1306-stm32HAL 的传输模式：`HAL_I2C_Mem_Write(DevAddr=0x78, MemAddress=0x00=命令寄存器/0x40=数据寄存器, ...)` 单笔发送，由 HAL 构造合法帧。命令与数据各走各的寄存器地址，禁止再手拼帧。

## 影响文件
- `firmware/soundDog/BSP/oled_drv.c`（oled_write_cmd / oled_update_screen 改 Mem_Write 模式）

## 验证方式
BUG-20260829-006 修复后（init 终于能执行到写屏阶段）一并上板复核通过：`err_count=0`（全部 Mem_Write 传输零 NACK/零超时）+ 屏幕正确显示自检画面/柱状图（无乱码、无条纹）。

**验证条件**（必填，R25）：
- 硬件/环境：本板 + OLED 0x3C + GDB err_count 读数 + 用户目视
- 验证的因果链：Mem_Write 0x00/0x40 分笔模式传输 → err_count=0 + 屏显内容正确（对比修复前的随机 GDDRAM 乱码）
- 结论级别：功能正常（BUG-006 阻塞解除后按 R24 首批复核完成）

## 通用教训（提炼至 lessons_summary）
1. 外设协议层（如 SSD1306 控制字节）语义错误不会在总线层报错——"HAL_OK"不等于"屏幕收到正确语义"，必须对照器件手册的帧格式定义。
2. 传输方式抄成熟项目（4ilo Mem_Write 模式），但电气参数要核对本硬件（见 R28 教训，BUG-006 案例反证）。
