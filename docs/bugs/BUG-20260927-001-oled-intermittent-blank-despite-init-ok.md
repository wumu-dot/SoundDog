# OLED 偶发上电黑屏/灰屏，但 I2C init 始终 OK——指向模块供电/电荷泵物理层

- **Bug ID**：BUG-20260927-001
- **严重等级**：P2-一般（偶发、按复位可恢复、固件链路无错）
- **发现日期**：2026-09-27
- **修复日期**：未修复（锁定为物理层，待硬件排查）
- **关联 FEAT**：FEAT-A2-03（OLED 频谱显示）

## 现象描述
OLED 屏**时亮时不亮**：多数上电自动正常显示，偶发上电后**黑屏或灰屏**，按复位几（多）次后恢复。灰屏时 CPU 明显活着（串口持续滚动频谱数据、喂狗正常），非整机死机。

## 复现步骤
1. 反复上下电若干次（每次间隔 1~2s）
2. 偶发次：屏黑/灰，此时串口仍正常持续输出 BANDS/SPEC/DMIN 等数据
3. 按复位键数次 → 屏恢复显示

## 根因分析
**固件侧已排除**，卡点锁定在「MCU→OLED 控制器（SSD1306）」之后、但「面板/电荷泵」之前的物理环节。证据链：
- 多次上电串口均为 `I2C scan: 0x3C (end)` + `OLED init OK (selftest grid)`，**零 NACK、零超时、`OLED i2c err` 从未出现**（见附件串口日志 10:45~10:46）
- 即 MCU 已把全部 26 条初始化命令成功写进 SSD1306 控制器，传输层完好
- 但控制器能应答不代表 charge pump 已起来：上电瞬间**模块 VCC 供电不足/波动**，SSD1306 可应答 I2C 而面板无驱动 → 黑/灰。复位让电源重新爬升，偶发爬够 3.3V 即点亮，故"按几次复位能好"

## 修复方案
**不涉及代码改动**（固件零改动，链路已证通）。硬件侧处置，按优先级：
1. 测 OLED 模块 VCC：上电瞬间到稳定需 ≥3.3V；跌落即供电/接线问题
2. 重插并加固 VCC/GND 两脚（RS485 联调搬动板后的头号松线嫌疑）
3. 换备件 OLED 复核：换上稳定 = 旧模块 charge pump/面板损坏

## 影响文件
- 无（固件不改动）。仅硬件接线/供电排查

## 验证方式
**上电 N 次（≥10）均正常亮起**，且中途无黑屏复现，方可关闭。

**验证条件**（必填，R25）：
- 硬件/环境：本板 + OLED 0x3C + 万用表测 VCC
- 验证的因果链：仅已验证「串口 init OK + I2C 链路通」（0x3C 应答、err=0），**尚未**验证「屏稳定持续点亮」→ 本 BUG 记为**待复核**，不得以链路通当已修复
- 结论级别：链路通（已证），功能稳定点亮（**未证**，待上电 N 次观察或换模块后复核）

## 通用教训（待提炼至 lessons_summary）
1. 偶发上电黑屏而 I2C init 全程 OK → 先判「控制链路 vs 面板/供电」是两回事：SSD1306 能应答 ≠ charge pump 已起、面板已点亮。不要因为链路通就改固件，优先怀疑模块 VCC 上电稳定性。
2. "按复位几次能好"是供电/电荷泵竞态典型特征，而非固件 bug。
