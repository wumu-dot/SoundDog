# I2S3 数据与 WS 槽存在 16 SCK 相位偏移，取数必须用高 16 位

- **Bug ID**：BUG-20260816-002
- **严重等级**：P1-严重（音频数据能收到但取数恒为 0，A1 验证无法通过）
- **发现日期**：2026-08-16
- **修复日期**：2026-08-16

## 现象描述

修复 BUG-20260816-001（DMA 溢出）后，DMA 数据正常流动、回调正常触发、RTOS 正常，但 `max=` 恒为 0。原始数据全为 `0x0000FFFF`（静音）或 `0xSSSSFFFF`（有数据时数据在高 16 位）。

## 复现步骤

1. 修复 BUG-20260816-001 后烧录
2. 串口看到 `[n] max=0` 恒为 0
3. 用诊断固件打印 DMA 原始数据：`RAW: 0000FFFF 0000FFFF ...`

## 根因分析

本工程 I2S3 的 32-bit 字边界与 INMP441 的 WS 槽边界存在 **16 SCK（半槽）相位偏移**：
- 帧结构 = `[16 位音频][16 位空闲/上拉电平(0xFFFF)]`
- 音频数据位于 32 位字的 **bits[31:16]**
- 原驱动 `I2S_DRV_ExtractPCM` 取 bits[23:8]（`raw>>8` 再 `>>8`），恰好跨在"数据低字节 + 空闲字节"上 → 静音时全 0

注：16 SCK 偏移的硬件成因未深究（疑为 INMP441 输出相位 vs STM32 Philips 采样的时序差），实测确定数据在高 16 位后软件补偿即可。

## 修复方案

`I2S_DRV_ExtractPCM` 改为 `(int16_t)(raw >> 16)`，直接取高 16 位作为 16-bit PCM（即 24-bit 采样中的有效位）。

## 影响文件

- `firmware/soundDog/Inc/i2s_drv.h`（I2S_DRV_ExtractPCM）

## 验证方式

- 静音：`max` 为 0 或极小值
- 说话/拍手：`max` 随声音明显变化
- 若以后修正 WS 相位使数据回到 bits[31:8]，需把取数改回 `(int16_t)(raw >> 8)` 语义（i2s_drv.h 内注释已写明）

## 遗留

- 本次用旧麦克风验证（麦克风疑似在超压事故中损坏，输出恒 0），修复正确性待新麦克风确认
- 采样率实测约为设计的 2 倍（帧节奏 31 帧/250ms），SCK 实际值待后续用示波器确认；不影响 A1 max 验证，A2 FFT 前需核实
