### 3.1 采集正常特征数据（A3-04 串口输出 → CSV，目标环境声）

1. 上电，确认串口出现 boot 三行 + `MFCC13 c=...` 行（1s 一行）。
2. **保持目标环境声**（设备部署环境的背景声，人确认的"正常"工况；全程避免吹气/敲击/突然说话等异常声）。**实际执行：人打开抖音模拟日常工厂环境声（人确认）。**
3. 运行 `python scripts/collect_mfcc.py data/mfcc_normal_600.csv --n 600`（自动前缀过滤 MFCC13 行、×100→float 还原、维数校验、600 帧自动停；预计 **\~10 分钟**）。
4. 记录：**实际帧数：600**（期望 ≥600；若丢弃行 >1% → 查串口质量）；**丢弃行数：0/600（0.00%）**。实际耗时 604s，节拍精确 1 帧/s。
5. 抽查：CSV 每行 13 个数（**期望 13 维**，记录实际维数：13，解析器逐行校验 0 丢弃）；c0 量级 |c0|<200（×100 已还原）。**实测 c0 范围 -30.98 \~ -4.50，无 c0<-90 静音地板帧。**

### 3.2 运行 K-means（K=16）

1. 运行 `python scripts/kmeans_model.py data/mfcc_normal_600.csv firmware/soundDog/BSP/model_normal.c`（**K=16 禁改**、seed=42 硬编码、n\_init=10）。
2. 记录输出：**簇中心数：16**（固定）；每个中心维度：**13**（固定）。
3. 检查各簇样本数（脚本打印各簇计数 + 空簇告警）：**各簇样本数：[50, 47, 78, 53, 17, 19, 13, 49, 14, 79, 44, 24, 7, 14, 26, 66]（总和 600，最小簇 7）**（任一簇=0 → 空簇 → 回 §3.1 补采 300 帧）。
4. 种子值：**42**（硬编码，重跑必然一致）。
5. 检查无静音地板簇（各簇 c0 均值分布——若某簇 c0≈-110 且其余维≈0 → 地板簇混入，回 §3.1 重采）。**脚本自检 [OK] 无空簇、无地板簇；整体均值 c0..c2 = -10.54 / -3.06 / +0.13。**
