## 0. 三源核对（R27）—— 结论与证据

| # | 待验设计点 | 源① 标准 / 权威 | 源③ 交叉验证 | 判定 |
|---|---|---|---|---|
| **V-1** | 加速度必须积分成**速度 RMS** 才能对标标准 | ISO 20816（取代 ISO 10816）：评价量 = **振动速度均方根**；测加速度须积分后再与限值比较 | 频域积分（FFT→每行 ÷ 2πf → IFFT）为现代分析仪标准做法，无累积误差；时域积分有漂移，仅在无法频域时使用 | ✅ **成立** |
| **V-2** | 积分前要高通、频带取 **10~1000 Hz** | ISO 10816/20816 规定消除 **10 Hz 以下**分量 | 多处一致：带通 10~1000 Hz 后再算 RMS | ✅ **成立**（但本硬件带宽上限 260 Hz，落地降为 10~250 Hz，见 §0.2） |
| **V-3** | 速度 RMS 能测到轴承故障 | — | ❌ **不能**：轴承故障在 **500 Hz~10 kHz**，且在速度谱里被 `1/ω` 压低（"在速度谱里权重很小"）；须用**加速度包络解调** | ⛔ **不能，须写明** |
| **V-4** | 温度可用"温升"作判据 | GB/T 755-2019 / IEC 60034-1：温升 = **绕组/轴承本体温度 − 环境温度**，轴承温升 ≤40 K、轴承温度 ≤95 ℃；须**预埋热电偶或电阻法** | GB/T 1032：环境温度用于**温升修正**，不是判据本身 | ⛔ **不成立**（SHT30 测空气，非本体）→ 改为**修正项** |
| **V-5** | 三级状态（正常/预警/报警） | ISO 10816 四区 A/B/C/D + ALARM 设在 B/C 界、TRIP 设在 C/D 界 | 工业实践普遍用黄/橙/红三级 | ✅ **成立** |
| **V-6** | 多通道联合判断（分诊）是工业做法 | — | 行业实践：低频速度超限 **AND** 高频包络超限才跳机；仅一路超限只预警并给方向 | ✅ **成立**（属实践，非标准，须标注） |

## 2. 目标：三模块同构

### 2.1 统一输出契约

每个模块都输出**同一种结构**：

```c
typedef struct {
    uint8_t  level;   /* 0=正常 1=预警 2=报警 */
    uint8_t  score;   /* 0~100 异常度 */
    uint16_t raw;     /* 原始量（供显示/调试）*/
    uint8_t  valid;   /* 0=数据无效/未就绪 */
} mod_result_t;
```

### 2.2 三模块的角色（**不是三个都出判据**）

| 模块 | 角色 | 判据来源 | 输出 |
|---|---|---|---|
| **声学** | **主判据** | 自建：MFCC 距离 vs 阈值 | `level` + `score` |
| **振动** | **次判据（趋势）** | **自建基线倍数**（mg 加速度 RMS/峰值）；**不做 ISO 分区**（带宽 260 Hz 天花板 + 设备功率未知） | `level` + `score` |
| **温度** | **辅助 / 修正** | 不单独判故障；提供环境温度用于**基线修正**；环境异常时给提示 | `修正系数` + `环境提示` |

⚠️ 这一条必须写进论文：**"三模块"≠"三个都判故障"**。温度是条件量，不是判据量——这是由 GB/T 755 的温升定义决定的，不是我们偷懒。

### 3.2 振动（新建，细节见 FEAT-A7-04，但**必须先改它两处寄存器配置**）

| 步 | 内容 | 依据 |
|---|---|---|
| 采集 | I2C2（PF1/PF0）读 `0x3B` 起 6 字节；**ODR=500 Hz**（`0x19=0x01`）、**DLPF=0（260 Hz）**（`0x1A=0x00`）、量程 ±8 g（`0x1C=0x10`） | 采样 ≥2× 带宽 |
| 去重力 | 上电静止 2 s 取三轴均值当零点 | A7-04 D-6 |
| 统计 | 1 s 窗口内去重力合成加速度 **RMS（mg）** 与**窗口峰值（mg）** | — |
| 判据 | **自建基线**：静止 10 min 得 μ 与 σ，报警线 = μ+kσ（k=3）；**不引用 ISO 分区** | V-7 + 带宽限制 |
| 异常度 | `s2 = min(100, 100·rms/(μ+3σ))` | — |
| 速度量（可选） | 频域积分（÷2πf）得 mm/s，**仅串口打印/论文分析用，不写寄存器、不参与判决** | V-1（受 250 Hz 带宽限制） |
| ⛔ 不做 | 轴承故障、ISO 分区对标、1000 Hz 以上任何结论 | V-3、V-7 |

> **§3.2.1 为什么必须改 A7-04 的采样配置**
> A7-04 现定 `0x19=0x09`（100 Hz）、`0x1A=0x03`（44 Hz）。44 Hz 低通会把 1×~3× 转频以上的成分直接削掉，频带根本到不了本节的 10~250 Hz。
> ⇒ P2a 先把 `0x19=0x01`、`0x1A=0x00`，并同步更新 A7-04 的 D-4 裁决（"44 Hz 保留尖峰"的理由在 500 Hz 采样下不再成立）。
> ⚠️ 若 I2C2 顶不住 500 Hz（T-6），退路是 `ODR=250 Hz` + `DLPF=1`（184 Hz），论文口径落 **10~90 Hz**，不得含糊成"10~250 Hz"。

### 3.3 温度（改角色）

| 项 | 做法 |
|---|---|
| 判据 | ❌ **不单独判故障** |
| 用途 1 | **基线修正**：环境温度偏离标定时温度 ≥ ΔT，则声/振阈值按比例放宽（避免夏天误报） |
| 用途 2 | **环境异常提示**：环境温度持续上升（如电箱通风不良）→ 单独提示，不并入设备报警 |
| 输出 | 修正系数 `k ∈ [0.9, 1.2]` + 环境提示 flag |
| **k 标定（P1 必做或必声明）** | 两个环境温度点（如 25 ℃ / 35 ℃）各静置 **10 min**，记录 s1 与振动 RMS 的均值变化，拟合 `k(ΔT)`。**未完成标定 ⇒ k 强制 1.0，并在串口/OLED 标「未标定」**（AC-10） |

> ⚠️ 若将来要真正测温升，必须加**贴片式传感器（PT100/DS18B20）贴在轴承座或机壳**，SHT30 做不到。这属硬件升级，本文不覆盖。

## 4. 融合与分诊

### 4.1 融合规则（简单可解释，不做黑箱）

```
S = max(s1, s2)                                  // 基线：取最严重的一路
if (s1 >= L1 && s2 >= L1) S = min(100, S + 10)    // 共现升级：两路同时越预警线 → 升一档
level = 0/1/2                                     // 由 S 的区间决定
主导通道 = argmax(s1, s2)
```

`L1` = 预警线（建议 40，与 level 区间定义在 P3 定死）。

**为什么先 max**：报警系统的原则是"任一路严重即报警"，加权平均会让某一路的高值被另一路的低值冲淡 —— 这在安全场景是错的。

**为什么再加共现升级（v2 新增）**：纯 `max` 等价于"两路各自报警"，融合没有增量语义，答辩无法解释"融合做了什么"。共现规则用 `(s1≥L1 ∧ s2≥L1)` 这一条可解释的时序条件，把"两路同时异常"从**预警**抬到**报警**——这正是 V-6 里"低频速度超限 AND 高频包络超限才跳机"的工程实践，且只多一行代码、不需要任何模型。

### 4.2 分诊输出（给运维的一句话）

| 情形 | 输出 |
|---|---|
| 全正常 | `正常` |
| 只有 s1 高 | `预警｜声学主导 → 查皮带/润滑/异物` |
| 只有 s2 高 | `预警｜振动主导 → 查地脚/配重/联轴器` |
| s1、s2 都 ≥ 预警线 | `报警｜声振共现 → 停机检查`（共现升级，见 §4.1） |
| 环境温度异常 | `提示｜安装环境温度偏高`（不计入设备报警） |

> 这套"分诊"逻辑的依据是 V-6（工业双通道联合判断实践），**不是标准条文**，论文中须标注。

### 4.3 跨仓库影响（决定"改不改 Modbus"）

**本轮（P1~P4）零改动**：`mod_result_t`（`level`/`score`/主导通道）只走 **OLED + 串口**，**不进 Modbus**。理由很实际：

- 寄存器从 9 扩到 12 ⇒ 从站 `MODBUS_REG_HOLDING_NUM`、网关 `MASTER_PARAM_CNT`、`sounddog_holding_t`、整块读字节数、云端属性、`tools/` 镜像与断言 —— **六处同步**，且两侧必须同一次烧录；漏改任一处就会整块读 **异常 0x02 全挂**（已有前科，见 SHT30 扩展规格 S5）。
- 同理，振动单位维持 **mg**：单改 mm/s 就要走上面 6 处里的 5 处，收益只是论文措辞。

**若将来确实要把三模块结论上云**，必须一次改全：

| 位置 | 改动 |
|---|---|
| 从站 `BSP/param.h` | `MODBUS_REG_HOLDING_NUM` 9 → 12 |
| 从站 `App/modbus_app.c` | `usRegHolding[9..11]` = level / score / 主导通道；只读属性靠 `reg_off_to_pid` 落 `default`（返回 0xFF ⇒ 写被 `MB_ENOREG` 拒），无需额外代码 |
| 网关 `main/mb_param.h` | `MASTER_PARAM_CNT` 9 → 12、`sounddog_holding_t` 加 3 个 `uint16_t` |
| 网关 `main/wifi_mqtt.c` + `tools/mqtt_payload.py` | payload 10 → 13 键；`PAYLOAD_FMT` 必须同步（反查测试会红） |
| ThingsCloud | 「功能定义」先建 3 个同名属性，否则平台 **406 拒收**（`wifi_mqtt.c:444` 已记此坑） |
| 网关 `tools/al_sim.py` / `modbus_slave.py` / 相关测试 | 寄存器模型 9 → 12，`ok=9` 判据同步 |

> ⚠️ 这是本文与 A7-04 的**硬边界**：A7-04 写的 `vib_rms/vib_peak`（mg）语义保持不变，本文不重定义。

## 5. 验证方法（这是本文最要紧的一节）

### 5.1 必须产出的四组数据

| # | 数据 | 怎么测 | 用途 |
|---|---|---|---|
| **M-1** | 声学**误报率** | 安静环境连续 1 h（约 3600 帧判决） | 支撑"能用"的最基本证据 |
| **M-2** | 振动**基线方差** | 静止 10 min，统计 **mg RMS 的均值 μ 与 σ** | 定自建基线（报警线 = μ+3σ） |
| **M-3** | **单源 vs 融合**对比 | 造故障（不平衡/松动）3 次，分别统计单源报警与融合报警 | **论文核心结果** |
| **M-4** | 分诊正确率 | 三次故障中，主导通道是否指向了真实施加的故障 | 支撑"分诊有用" |

### 5.2 故障制造（可重复）

| 故障 | 制造方法 | 预期主导通道 |
|---|---|---|
| 不平衡 | 风扇/联轴器**贴配重** | 振动（1× 增大） |
| 松动 | **松一个地脚螺栓** | 振动（亚谐波） |
| 声学异常 | 摩擦/异物（如轻触旋转件、放异物） | 声学 |

### 5.3 判据（通过线）

| # | 通过线 |
|---|---|
| AC-1 | 声学误报率 ≤ 1 次/h（安静环境） |
| AC-2 | 振动静止时 RMS 波动 `σ ≤ 0.05·μ`（比例口径；绝对值由 M-2 实测后回填，不预设 mg 数字） |
| AC-3 | 三次故障中，至少 2 次能在 10 s 内产生报警 |
| AC-4 | 融合报警**不晚于**单源报警超过 5 s（不能因融合而迟钝） |
| AC-5 | 分诊主导通道 3 次中至少 2 次正确 |
| AC-6 | 不影响既有功能（OLED/Modbus 联跑 30 min 零错误） |
| AC-7 | 无测试遗留 |
| **AC-8** | 带宽口径一致：固件实际配置 `0x19=0x01`/`0x1A=0x00`，串口/文档声明 10~250 Hz；**不得出现 1000 Hz 或 ISO 分区结论** |
| **AC-9** | 共现升级实测：构造 s1=s2=预警线的场景，输出等级必须是**报警**（2）而不是预警（1） |
| **AC-10** | 温度 k 未标定时必须 = **1.0**，且串口/OLED 有「未标定」提示 |
| **AC-11** | Modbus 零改动回归：寄存器仍 9，网关整块读 `ok=9` 不下降（证明 §4.3 成立） |

> **最小可行版（时间紧时）**：P1 + P3 + P4 只接声学/温度两路，振动以"寄存器 7/8 恒 0 + `valid=0`"占位 ⇒ 2~3 天即可产出"三模块同构 + 分诊"的完整叙事，P2/P5 后补。这样做的代价是论文里振动章节只能写"接口已就绪、数据待接入"，不能写振动结论。
>
> **P3 的红线**：`mod_result_t` 只能**旁挂**在 `mel_frame_cb` 之后新增一条只读输出，⛔ 不得改动 `debounce_process` 的调用与参数，⛔ 不得动 `modbus_app.c` 的 9 个寄存器（避免把已验收的 A4-04 拖回未验证状态）。

## 7. 能力边界（必须写进论文，不能含糊）

| 能 | 不能 |
|---|---|
| 判断"设备是否偏离正常" | 判断"是哪种故障、哪个部件" |
| 输出振动**趋势量**（mg 加速度 RMS/峰值），用自建基线（μ+3σ）判断偏离 | **输出 ISO 10816/20816 振动烈度（mm/s）并对标分区**（本硬件带宽 10~250 Hz，评价带要 10~1000 Hz） |
| 给出"哪一路主导"的分诊建议 | 测轴承早期故障（速度谱里被压低，见 V-3） |
| 环境温度补偿，降低季节误报 | 测设备本体温升（SHT30 做不到，见 V-4） |
| 两路共现时自动升级报警等级 | 给出故障频率证据 |

## 9. 与 FEAT-A7-04 的关系

- **本文**：系统的判据架构（三模块同构 + 融合 + 验证方法）
- **FEAT-A7-04**：振动通道的实施细节（I2C2 接线、寄存器序列、量程/DLPF 选择）
- 两者不重复：A7-04 回答"怎么读到振动"，本文回答"读到之后怎么变成结论"
- ⚠️ **v2 起两者有一处强制联动**：本文 §3.2 要求 `0x19=1`/`0x1A=0`（500 Hz / 260 Hz），A7-04 现为 `0x09`/`0x03`（100 Hz / 44 Hz）⇒ **P2a 必须先改 A7-04 并回填其 D-4 裁决**，否则本节频带无法成立
