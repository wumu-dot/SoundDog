# Agent 傻瓜式操作单 · 统一规格（SOP 规范）

> **用途**：本文件定义"傻瓜式操作单"的格式与 Agent 执行铁律。所有子 FEAT 文档（新建或重写）必须遵守本规格。
> **目标**：任何一个**没有对话上下文**的 Agent，只读文档即可独立、正确、不越界地执行完 5 阶段。
> **地位**：与 `.template-child.md`（最小骨架）配合；本规格是"细化实施层"。事实以 `pin_config.h` / `HANDOFF.md` / 本规格 §3 为准，**Agent 禁止猜测、禁止自造数值**。

## 0. 文档体系

* 父 FEAT = 规划（Planner 角色），子 FEAT = 执行（Dev → Test → Review 角色）。

* 父 FEAT 文档：项目表 + 依赖顺序 + 阻塞（规划层，不写实现）。

* 子 FEAT 文档：5 阶段执行 + §3 傻瓜式操作单（执行层，照做即可）。

* 新建子 FEAT 文件命名：`FEAT-{A1}-{NN}-{中文描述}.md`，并在父 FEAT 项目表「文件」列回填。

## 1. Agent 执行铁律（防翻车 · 硬性，违反即退回）

### 1.1 动手前必读（按任务类型）

| 要做什么      | 必读文件                                                                 |
| --------- | -------------------------------------------------------------------- |
| 任何代码改动    | `CLAUDE.md`（硬边界）+ `PROJECT_PLAN.md` §5.1（任务规划）+ 本 FEAT 文档            |
| 硬件接线/测量   | `HANDOFF.md` §4.2 + `firmware/soundDog/Inc/pin_config.h` + 本 FEAT §3 |

### 1.2 绝对禁止（红线）

1. 禁止修改 `firmware/Drivers/` 下任何 HAL 库文件。
2. 禁止未读 §1.1 必读文件就动手改代码。
3. 禁止跳阶段 / 自审自判：阶段 4 必须 Test 角色独立验证，阶段 5 必须 Review 角色独立审查。
4. 禁止删除/篡改执行日志中已完成的历史行（只允许追加新行、更新状态字段）。
5. 中断优先级 0~~4 禁止调用 FreeRTOS FromISR API（仅 5~~15 可安全调用）。
6. 禁止在 ⏸️ 停等点未获人确认"继续"前进入下一阶段。
7. 禁止为"通过"而编造证据——无证据的"看起来正常"一律视为未通过。

### 1.3 判定标准（有客观证据才算通过）

| 验证项   | 通过证据（必须记录实际值）                          |
| ----- | -------------------------------------- |
| 编译    | `build.bat` 无错误退出，无新增警告                |
| 烧录    | OpenOCD 输出 `wrote ...` / `Verified OK` |
| 串口    | 抓到的 boot 三行 + `max` 数值变化（记录读数）         |
| 硬件电压  | 万用表读数落在期望区间（记录数值）                      |
| 逻辑分析仪 | 实测 SCK 频率在期望 ±5%（记录数值）                 |

## 3. 项目事实包（Agent 唯一事实来源 · 禁止自造数值）

### 3.1 芯片与时钟

* STM32F407ZGT6；HSE=8MHz → SYSCLK 168MHz（PLLM=8/PLLN=336/PLLP=2）。

* I2S3：PLLI2SR=5 → I2SxCLK=51.2MHz；I2SDIV=25 → SCK=1.024MHz；Fs=SCK/64=16kHz。

* NVIC 分组 4；`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5`；TIM7=HAL 时基、SysTick=FreeRTOS tick。

### 3.2 引脚（权威 `pin_config.h`，改引脚只改此文件）

| 功能      | 引脚                                 | 备注                                                               |
| ------- | ---------------------------------- | ---------------------------------------------------------------- |
| I2S3 WS | PA4                                | 主模式                                                              |
| I2S3 CK | PB3                                | SCK，预期 1.024MHz                                                  |
| I2S3 SD | PB5                                | INMP441 SD，建议 4.7kΩ 上拉至 3.3V                                     |
| LED 红   | PB0                                | TIM3\_CH3，串 220Ω                                                 |
| LED 绿   | PB1                                | TIM3\_CH4，串 220Ω                                                 |
| 蜂鸣器     | PE6                                | 三极管驱动                                                            |
| OLED    | I2C1（PB6 SCL / PB7 SDA）            | SSD1306 0.96"，地址 0x3C/0x3D                                       |
| SHT30   | I2C1                               | 温湿度传感器                                                           |
| RS485   | USART3 + TTL-RS485 模块(3.3V/SP3485) | 模块引脚：**EN/VCC/A/B/GND×2/RXD/TXD**；EN=方向使能（高=发送/低=接收）接 GPIO(PD11) |
| 调试串口    | USART1                             | 115200                                                           |

### 3.3 构建与烧录

* 编译：`firmware\build.bat`（mingw32-make + arm-none-eabi-gcc）。

* 烧录 SWD：`firmware\build_and_flash.bat`（期望 `wrote ...` / `Verified OK`）。

* 兜底 ISP：`firmware\flash_isp.bat`（BOOT0 + USART1，见 HANDOFF §4.3）。

* Makefile 手动加源文件到 C\_SOURCES（BUG-002 教训：漏加导致链接失败）。

### 3.4 串口输出（USART1 · 115200）

* 开机三行：`SoundDog boot OK` → `I2S_DRV_Init ret=0` → `I2S DMA started`。

* 采集打印：`[n] max=xxxx`，max 随吹气/敲击明显变化。

* SSCOM 打开，COM 口以设备管理器为准（不一定是 COM4）。

### 3.5 已知 Bug（引用 `docs/bugs/`）

* BUG-20260816-001：`HAL_I2S_Receive_DMA` Size 翻倍溢出（已修：传半缓冲）。

* BUG-20260816-002：I2S 数据槽偏移，取数用 `(int16_t)(raw & 0xFFFF)`。
