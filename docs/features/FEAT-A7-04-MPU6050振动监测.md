## 1. 🔴 三源核对发现：旧规格有 5 处与现状不符（必须先裁决）

| # | 旧规格写的 | 实际情况 / 厂商原文 | 裁决 |
|---|---|---|---|
| **D-1** | §4.3：振动寄存器放 `0x0005`/`0x0006`，「从站 `MODBUS_REG_HOLDING_NUM` 5→7」 | 从站**已扩到 9**：`0x0005=温度`、`0x0006=湿度`（SHT30），`0x0007=VIB_RMS`、`0x0008=VIB_PEAK` 已预留且恒 0（`modbus_app.c:110-111`） | ✅ **按 7/8 实施**。旧规格的 5→7 已过时，**协议层零改动** |
| **D-2** | §2.6.3b：走 **USART2**（PD6=RX / PD5=TX） | 代码注释却写「MPU6050（**I2C2**）尚未接入」（`modbus_app.c:20-25`）；`pin_config.h:61-62` 只有 I2C2 备选定义（PF1/PF0），**无 USART2/PD5/PD6 宏** | ✅ **按 USART2 实施**；**同步改掉 I2C2 那条注释**（它是 A 方案残留，会误导后人） |
| **D-3** | §4.2：换算按 **±2 g / 16384 LSB/g** | 说明书 p2「量程：加速度 **±16 g**」；示例 `main.c:19` 为 `/32768.0*16` | ✅ **按 ±16 g**。旧规格 §4.2 属于 A 方案（I2C 直读可配量程），**串口版量程固定，不可配** |
| **D-4** | §2.6.4 只写「字节 8~9 = 温度」，无公式 | 说明书 p6：`T = ((TH<<8)|TL)/340 + 36.53 ℃`；**但厂商 `示例程序/核心代码/main.c:22` 写的是 `+36.25`** | ⚠️ **厂商资料自相矛盾**。本项目**不使用温度**，仅在代码注释标注，不据此做任何换算 |
| **D-5** | §2.6.4 给了校验和定义，但未说明厂商示例是否校验 | 说明书 p6 明确：`Sum = 0x55 + Type + D0..D7`（第 0~9 字节累加取低 8 位）；**而厂商 `usart.c` 的接收中断只判帧头 `Re_buf[0]!=0x55`，完全没有校验 Sum** | ✅ **实现必须校验 Sum**。示例代码是"能跑就行"，不能照抄；总线误码会直接变成假振动数据 |

**另有两处厂商资料内部不一致，记录备查（不影响本设计）**：

- 分辨率：说明书 p2 写「加速度 **6.1e-5 g**」，但按协议换算 `16 g / 32768 = 0.488 mg = 4.88e-4 g`。前者应是 MPU6050 在 ±2 g 档的指标，**串口版实际分辨率以换算为准 = 0.488 mg/LSB**。
- 温度系数：见 D-4。

## 2. 目标与范围

### 2.1 要做的

1. 从站通过 **USART2** 接收模块 100 Hz 数据流，解析 `0x51`（加速度）包；
2. 计算**振动趋势量**：三轴合成加速度去重力后的 **RMS** 与**窗口峰值**；
3. 写入 Modbus 保持寄存器 `0x0007` / `0x0008`（mg 定点，`0~5000`）；
4. 网关按既有 9 寄存器整块读上传云端（`vib_rms` / `vib_peak` 两个属性已建好，**无需改云端**）。

### 2.2 明确不做的

| 不做 | 原因 |
|---|---|
| 频谱分析 / FFT 诊断 | 模块输出 100 Hz，奈奎斯特 50 Hz；且数据经模块内部滤波，做频谱无意义（旧规格 M7 已定） |
| 姿态角（Roll/Pitch/Yaw）上传 | 寄存器只有 7/8 两位；如将来要用需再扩，本轮不做 |
| 温度上传 | 已有 SHT30，且模块温度系数厂商资料矛盾 |
| I2C 模式（A 方案） | 旧规格 §2.6.3 已论证：OLED 每 200 ms 独占 I2C1 约 23 ms ⇒ 采样被周期性阻塞 |
| 数据就绪中断（INT 脚） | 轮询/流式接收即可 |

## 3. 硬件前提

### 3.1 接线（串口模式，出厂默认）

| 模块引脚 | 接到 | 板上丝印 | 说明 |
|---|---|---|---|
| `VCC` | `3V3` | `3V3` | 说明书 p2：**3.3 V 或 5 V 输入**（内部稳压） |
| `GND` | `GND` | `GND` | 共地 |
| `TX` | **`PD6`** | `D6` | **USART2_RX**（模块发 → MCU 收） |
| `RX` | **`PD5`** | `D5` | **USART2_TX**（MCU 发 → 模块收，仅发指令用） |
| `SCL` / `SDA` | **悬空** | — | 串口模式不接 |

⚠️ **TX/RX 必须交叉**：模块 `TX` 接 MCU `RX`。这是串口接反的第一大坑。

### 3.2 引脚占用核对（已实测，非推测）

| 外设 | 占用引脚 | 出处 |
|---|---|---|
| I2S3（音频） | PA4 / PB3 / PB5 | `i2s_drv.c` |
| USART3（RS485） | PD8 / PD9 | `pin_config.h` |
| I2C1（OLED） | PB6 / PB7 | `i2c.c` |
| I2C3（SHT30） | PA8 / PC9 | `sht30.c` |
| **USART2（本次）** | **PD5 / PD6** | ✅ 全仓 grep：业务代码对 GPIOD pin5/pin6 零引用；`USART2` 仅出现在 CMSIS 头文件 |

### 3.3 供电与地

- 模块 <10 mA，从板载 3V3 取电即可；
- ⛔ **不要接 5 V 到 PD6**（若模块 5 V 供电，其 TX 电平也是 5 V，直连 MCU 会打坏 GPIO）。本设计统一用 **3V3**。

### 5.2 修改文件

| 文件 | 改动 | 风险 |
|---|---|---|
| `sources.mk` | `PROJECT_C_SOURCES` 加 `BSP/mpu6050.c` | 低（唯一构建入口） |
| `Inc/pin_config.h` | 新增 `MPU_UART` / `MPU_RX_PIN(PD6)` / `MPU_TX_PIN(PD5)` 宏 | 低 |

| `App/modbus_app.c` | 删除本地 `g_vib_rms/g_vib_peak` 定义 → 改为 `#include "mpu6050.h"` 提供 extern；修正 I2C2 注释 | 低 |

### 5.3 接收方案：DMA 循环 + IDLE 中断

| 项 | 值 | 理由 |
|---|---|---|
| 数据率 | 100 帧/s × 33 B = **3.3 KB/s** | 占 115200 带宽 29% |
| 方案 | `HAL_UART_Receive_DMA`（循环模式）+ `HAL_UARTEx_ReceiveToIdle_DMA` 或 IDLE 中断 | 逐字节中断 = 11.5k 次/s，可行但浪费；DMA+IDLE 一次中断处理 ~33 B |
| 缓冲 | 双缓冲各 **128 B**（≥3 帧），DMA 半满/全满回调交替解析 | 33 B/10 ms，128 B ≈ 38 ms 余量 |
| 失步恢复 | 状态机只在**期望位置**找 `0x55`；校验失败则**整体丢弃并从下一字节重新找帧头** | 不能"只信帧头"（D-5：厂商示例的弱校验会导致假数据） |

### 5.4 帧解析规则（据说明书 p6）

```
帧长 11：[0]=0x55 [1]=type [2..3]=XL/XH [4..5]=YL/YH [6..7]=ZL/ZH [8..9]=TL/TH [10]=Sum
Sum 校验： (0x55 + type + D0..D7) & 0xFF == [10]
type: 0x51=加速度  0x52=角速度  0x53=角度  0x50=模块处于 I2C 模式（异常态）
换算： ax = (int16)(XH<<8|XL) / 32768.0 * 16   （单位 g）
```

**异常处理**：若收到 `0x50` 包 ⇒ 模块被切到 I2C 模式 ⇒ 从站主动发 `FF AA 61`（切回串口）+ `FF AA 63`（115200/100Hz），并置错误计数。

### 5.5 振动量算法

| 步 | 做法 | 说明 |
|---|---|---|
| 1 | **上电跳过前 3 s** | 说明书 §6.1 注 1：模块上电需静止自动校准，Z 轴角度归 0 为完成信号；校准期间数据不可用 |
| 2 | **零点标定**：静止 2 s（约 200 帧）取三轴均值 `gx,gy,gz` | 静止时合成 ≈1 g，不减掉则 RMS 恒 ≈1 g，看不出小振动 |
| 3 | 每帧去零点：`dx=ax-gx` … | — |
| 4 | 窗口累加：`sum += dx²+dy²+dz²`，`peak = max(peak, sqrt(dx²+dy²+dz²))` | — |
| 5 | **每 100 帧（1 s）**结算一次：`rms_mg = sqrt(sum/N)·1000`，`peak_mg = peak·1000` | 1 Hz 刷新寄存器，避免读半窗 |
| 6 | **限幅**到 `0~5000` 后写 `g_vib_rms` / `g_vib_peak` | 与旧规格 §4.3 范围一致；超量程说明真的振得厉害，截顶并在日志告警 |

**分辨率参考**：`16 g / 32768 = 0.488 mg/LSB` ⇒ 1 mg 以下无法分辨，寄存器用 mg 整数刚好匹配（见 §1 分辨率矛盾说明）。

### 5.6 优先级与阻塞

| 项 | 值 |
|---|---|
| `vibTask` 优先级 | `osPriorityBelowNormal`（与 `sht30` 同级） |
| 栈 | **1024 B**（只做定点/浮点累加 + 一次 sqrt） |
| 阻塞点 | 只读共享变量、不做 I2C/UART 阻塞调用 ⇒ 不影响 Modbus 轮询 |

## 6. 实施阶段（每阶段有闸门，不通过不进下一阶段）

| 阶段 | 内容 | 闸门（必须实测通过） |
|---|---|---|
| **S1** | 只做 USART2 + DMA 接收，`printf` 打**原始字节**（hex） | 串口出现周期性 `55 51 …` 三包循环；**Sum 校验通过率 > 99%**；若一直无数据 ⇒ 先查 TX/RX 交叉 |
| **S2** | 帧状态机 + 解析出 `ax/ay/az`（g） | 静止时 `|a| ≈ 1.00 g ± 0.05`；翻动模块三轴变化方向正确 |
| **S3** | 零点标定 + RMS/峰值，1 Hz 打印 | 静止 30 s：`rms < 20 mg`；轻敲桌面：`rms` 明显上升后回落 |
| **S4** | 接入寄存器 7/8 + 云台上行 | 云端 `vib_rms` 不再是 0；轻敲时曲线起跳 |
| **S5** | 清理（见 §8）+ 长跑 | 见 §7 判据 |

## 7. 验收判据（AC）

| # | 判据 | 方法 | 通过线 |
|---|---|---|---|
| **AC-1** | 链路通 | 原始字节流 | 每秒稳定收到 100 帧 × 3 包，Sum 校验 > 99% |
| **AC-2** | 数值正确性 | 翻转模块 | `|a|` 恒在 1 g 附近；重力方向随姿态改变 |
| **AC-3** | **R25 功能验证（必须）** | **扰动输入看输出跟随**：静止→敲桌面→静止 | `rms` 从 <20 mg 起跳，峰值出现后 1~2 s 内回落 |
| **AC-4** | 线性度（J-2 待实测项） | 用手以不同力度轻敲三次 | 三次 `rms` 单调递增（不要求绝对线性） |
| **AC-5** | 不影响既有功能 | 与 SHT30/OLED/Modbus 同时跑 | 温度湿度照常；OLED 无卡顿；Modbus 9 寄存器零错误 |
| **AC-6** | 云端可见 | ThingsCloud 属性历史 | `vib_rms`/`vib_peak` 有非零值且与串口日志一致 |
| **AC-7** | 堆余量 | SWD 读 `xFreeBytesRemaining` | 加 `vibTask` 后仍需 **≥ 14,000 B**（当前 16,808 − 约 1,116） |
| **AC-8** | 无测试遗留 | 全仓扫描 | 无 `PROBE`/临时 printf/调试宏；一次性脚本不入库 |

## 8. 风险与坑

| # | 风险 | 表现 | 对策 |
|---|---|---|---|
| **M1** | **TX/RX 接反** | 完全无数据 | 交叉接线；S1 阶段先只看原始字节 |
| **M2** | 模块被切成 I2C 模式 | 串口只有 `0x50` 包 | 收到 0x50 自动发 `FF AA 61` 切回 |
| **M3** | 上电不静止 ⇒ 零漂没校准 | 静止时 `rms` 偏大且漂 | 上电 3 s 数据丢弃；必要时发 `FF AA 52`（角度归零） |
| **M4** | 只校验帧头不校验 Sum | 误码变成假振动 | **强制校验 Sum**（D-5） |
| **M5** | PD5/PD6 与既有外设冲突 | 引脚无输出/UART 异常 | 已核（§3.2）；实施前再 grep 一次 |
| **M6** | 堆不够 ⇒ 复位循环 | OLED 反复播开机动画、`[FATAL] FreeRTOS heap allocation FAILED` | 见 BUG-20261029-001；加任务后必读 `xFreeBytesRemaining` |
| **M7** | 杜邦线过长/接触不良 | 偶发丢帧、Sum 错 | 线 ≤20 cm；错帧率 > 5% 时先查线 |
| **M8** | 误把 5 V 供电模块的 TX 直连 PD6 | 打坏 GPIO | 统一 3V3 供电 |
