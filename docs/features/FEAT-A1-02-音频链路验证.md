## 3. 傻瓜式操作单（照做即可）

### 3.0 物品/工具清单
- [ ] 核心板（已按 A1-01 接好 INMP441）
- [ ] ST-Link（SWD：SWDIO/SWCLK/GND/3.3V 四线）
- [ ] USB-TTL（CH340）+ SSCOM（115200）
- [ ] 5V 电源（非快充）

### 3.1 烧录（阶段 3 执行）
1. 打开 `firmware` 目录，**双击 `build_and_flash.bat`**。
2. 等待：先编译（gcc 输出），再 OpenOCD 烧录，最后应看到烧录成功提示（`wrote ... bytes` / `Verified OK`）。
3. **失败兜底**：
   - OpenOCD 报连不上 → 检查 ST-Link 四线（SWDIO/SWCLK/GND/3.3V）是否接对、驱动是否装好，重试。
   - 仍不行 → 用 **`firmware\flash_isp.bat`**（BOOT0 拉高 + USART1 串口烧录，操作见 HANDOFF §4.3）。
4. 烧录成功 → 拔掉 BOOT0（若用过 ISP），断电重上电。

### 3.2 串口观察（阶段 4 执行）
1. USB-TTL 接核心板：TX↔RX **交叉**、GND 共地。
2. SSCOM 打开**设备管理器里看到的 COM 口**（不一定是 COM4），波特率 **115200**。
3. 按复位键，期望**依次**出现三行（2026-08-28 固件：BUG-002 v10 修复 + 诊断代码已清理；RS485 回环已 `#if 0` 关闭，无 RS485 打印）：
   ```
   SoundDog boot OK, SYSCLK=168000000
   I2S_DRV_Init ret=0 (0=HAL_OK)
   I2S DMA started! waiting data...
   ```
4. 对麦克风**吹气/轻敲**：`[n] max=xxxx` 数值应**明显变化**，节奏跟随声音。
   **v10 基准**（2026-08-28 17:58 复测实测，BUG-002 详解文档有完整数据）：
   - 安静：max ≈ **98 ~ 2352**（底噪 + 环境声）
   - 吹气：max ≈ **4577 ~ 32767**（多次打满 int16 满量程）
   - 判据：安静/吹气对比 ≥ 5 倍，且响应跟随动作节奏

### 3.3 故障速查表
| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 编译报错 | 工具链/路径问题 | 截图报错，查 `firmware\build.sh` 或 CI |
| OpenOCD 连不上 | ST-Link 接线/驱动 | 查 SWDIO/SWCLK/GND/3.3V；换 `flash_isp.bat` |
| 串口完全无输出 | TX/RX 没交叉 / COM 口错 / GND 未共地 | 交叉接、看设备管理器、共地 |
| 只有 boot 前几行就停 | 供电不稳 | 量 5V/3.3V（A1-01 §3.2），换电源 |
| 输出全 0xFF/0x00 | L/R 悬空 / 模块 SD 无输出 | 确认 L/R→GND（A1-01 §3.1）；查 BUG-002 详解文档 §3 的 4 字周期模式比对 |
| `max` 恒为小值（~几十）且吹气不变 | 麦克风 SD 无输出 | 轻敲/吹气确认；无反应 → 换模块（A1-01 §3.5） |
| `max` 恒 ~32000 且吹气不变 | v9 伪迹特征（提取了悬空字） | 确认固件是 v10 之后版本（i2s_drv.c 顶部注释标 v10） |
| 数值恒定不变 | 麦克风损坏 | 轻敲/吹气；无反应 → 换模块（A1-01 §3.5） |
