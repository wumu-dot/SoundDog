## 1. 总体目标与硬边界

### 1.1 核心目标（一句话）
> 用 **Python + pySerial** 实现 PC 端串口通信层：按 A5-02 帧协议（0xA5/0x5A/CRC16）与板端**双向收发无误码**，为 A8-02 频谱显示、A8-04 参数报警提供可靠数据管道。

### 1.4 关键参数与接口（事实包 §3 + 父 FEAT-A8，禁止自造）
- **串口**：CH340 的 COM 口（设备管理器为准），波特率 **115200**（`RS485_UART_BAUD`）。
- **帧协议**：帧头 **0xA5** / 帧尾 **0x5A** / **CRC16**（事实包 A5-02；CRC 多项式/帧字段格式**待定（需人确认，以 A5-02 阶段2 定稿为准）**）。
- **半双工**：同一时刻只允许一端发送（事实包 A5-01）。
- **运行环境（事实包 §3.7 实测 2026-08-16）**：**Anaconda `C:\Users\wumu2\anaconda3\python.exe`（3.13.5）**，numpy/scipy/matplotlib/scikit-learn 已装；**需补装 `pyserial`**（`python.exe -m pip install pyserial`，阿里云镜像）；⚠️ **勿用 conda 命令**（本机 conda 有 bug）。

### 3.4 故障速查表
| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 打开串口失败 | COM 被占用 / 端口号错 | 关闭 SSCOM 等其他占用程序；设备管理器核对 COM |
| 收不到回环 | 物理链路（A5-03）没通 / 半双工时序错 | 先跑 A5-03 验证；发完等接收完成再发下一帧 |
| 乱码 | 波特率不是 115200 | 两端改 115200 |
| 坏帧未丢弃 | CRC16 参数与板端不一致 | 对照 A5-02 定稿核对多项式/初值/位序 |
| 拔线后卡死 | 无超时处理 | 确认 recv 有超时（100ms 待定需人确认） |
| CRC 计算不符 | 实现与板端算法不同 | 与板端交换已知向量测试（A5-02 提供） |
