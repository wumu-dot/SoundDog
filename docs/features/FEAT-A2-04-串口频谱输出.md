## 1. 总体目标与硬边界

### 1.1 核心目标（一句话）
> 调试串口（USART1 115200）周期输出一行 32 个整数（频带能量），节流 ~200ms，供 PC 端绘图验证频谱正确性。

### 1.2 地基触碰前置自检
- [x] 否 → 继续（仅打印格式/节流改动，不碰底层库）

### 1.3 任务边界
| 类型 | 具体内容 |
|------|----------|
| 范围内（可改） | 串口打印格式与节流（`firmware/soundDog/Src/main.c` 或等效打印位置） |
| 超出范围（禁止碰） | `firmware/Drivers/` HAL 底层库 |
| 外部依赖 | A2-02 频谱（32 频带能量）、SSCOM 串口助手 |

### 1.4 关键参数与接口（权威：事实包 §3.6 A2-04 + §3.4）
- **串口一行 32 个整数（能量）**，便于 Excel/Python 画图。
- **节流 ~200ms** 一次，避免刷屏阻塞任务（与 A2-03 TaskDisplay 周期一致）。
- 调试串口 USART1 **115200**；boot 三行：`SoundDog boot OK` → `I2S_DRV_Init ret=0` → `I2S DMA started`。
- 数据源 = A2-02 的 32 频带能量（与 A2-03 OLED 同一数据源）。

### 3.2 串口观察（阶段 4 执行，AC-01 证据）
1. SSCOM 打开设备管理器中的 COM 口（不一定是 COM4），波特率 **115200**。
2. 期望每 ~200ms 输出一行、**每行 32 个整数**。**粘贴 3 行样本：**
   ```
   BANDS 78,8,11,7,5,8,6,6,7,3,5,3,4,2,2,3,2,3,2,3,2,2,2,1,2,2,1,2,1,1,1,1
   BANDS 33,14,15,12,9,5,3,6,2,4,3,4,1,2,4,2,4,1,2,4,2,2,1,1,1,1,2,2,2,1,1,1
   BANDS 12,10,7,11,6,6,4,4,2,3,3,2,4,4,2,2,3,2,2,2,2,1,1,1,2,2,2,2,2,1,1,1
   ```
3. 数一行整数个数 = 32（**记录：=32，逐行核对 ✓**）。
4. 吹气/说话：数值随声音变化。**记录变化范围：安静时低频带 9~52 → 发声时 78~1127（×100 整数域）；max 帧 782~32768（削波）**
5. 与 OLED（A2-03，若已通过）趋势一致：同一数据源，柱高与数值同涨落。**记录：同源同涨落 ✓（用户目视"会动" + 同一 bands 数组）**

### 3.3 故障速查表
| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 乱码 | 波特率不对 | 改为 115200 |
| 行内不足 32 个整数 | 打印截断 / 缓冲不足 | 增大打印缓冲或分批打印（方案：待定（需人确认）） |
| 长时间不输出 | 节流卡死 / 任务阻塞 | 检查打印任务调度；节流用非阻塞延时 |
| 数值全 0 | 数据源（A2-02）问题 | 查 A2-02 §3.5 故障表 |
| 数值不随声音变化 | 麦克风/取数问题 | 查 A1-02 / A1-03 |
| 输出影响采集（`[n] max` 卡顿） | 打印过长刷屏阻塞任务 | 确认节流 ~200ms；缩短单行或降频 |
