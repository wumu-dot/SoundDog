## 1. 总体目标与硬边界

### 1.1 核心目标（一句话）
> 确认有效 PCM 数据落在左声道还是右声道，固化取数掩码，为 A2 FFT 提供干净数据源。

### 1.2 地基触碰前置自检
- [x] 否 → 继续（不改底层库，仅确认取数逻辑）

### 1.3 任务边界
| 类型 | 具体内容 |
|------|----------|
| 范围内（可改） | `i2s_drv.c` 取数逻辑/打印（如需改声道索引） |
| 超出范围（禁止碰） | `firmware/Drivers/` HAL 底层库 |
| 外部依赖 | 已跑通的音频链路（A1-02）、SSCOM |

### 1.4 关键参数（事实包 §3，2026-08-28 更新至 v10 语义）
- L/R→GND = **左声道**（INMP441 手册约定）；L/R→3.3V = 右声道。
- v10 数据结构（BUG-002 RAW dump 确诊）：4 字周期 `[音频字][xx7F][FFFF][FFFF]`，INMP441 **只在自己的槽内驱动 SD**，其余时段高阻（被上拉成 0xFFFF）。
- 当前固件 `extract_frame` 步进 4 取 `word[4k]` 低 16 位（左声道模式实测标定）。
- **推论（本 FEAT 要验证的核心）**：L/R 切到 3.3V 后 INMP441 改在右槽驱动 → 音频字移位 → step-4 窗口取到悬空字 → max 掉回底噪。档位 B "无响应" 本身就是"左声道有效"的证据。
- 串口打印 `[n] max=xxxx`，max 随吹气变化 = 该声道有数据。

## 3. 傻瓜式操作单（照做即可）

### 3.0 物品/工具清单
- [ ] 核心板（已按 A1-01 接线、A1-02 验证通过）
- [ ] SSCOM（115200，COM 以设备管理器为准）
- [ ] 杜邦线 ×1（临时改 L/R 接线用）

### 3.1 档位A：L/R→GND（左声道，当前接线）
1. 上电，SSCOM 打开，确认串口出现 boot 三行 + `[n] max=xxxx`。
2. 对麦克风吹气 3 秒，观察 max：**记录数值范围：___ ~ ___**
3. 若 max 随吹气明显变化 → 左声道有数据；若恒 0 或恒定 → 查 §3.4。
4. **基准参照（A1-02 18:40 实测）**：安静 160~1606，吹气 2307~32767 多次打满。

### 3.2 档位B：L/R→3.3V（右声道）
1. **断电**，把 L/R 从 GND 改接到 3.3V（杜邦线）。
2. 上电，SSCOM 观察，吹气 3 秒：**记录数值范围：___ ~ ___**
3. **v10 判读标准**：
   - 预期 max 掉到底噪水平（几十~几百）且吹气**无响应** → 音频字已移位出 step-4 窗口 → **左声道唯一有效，结论固化，档位 A 恢复接线**
   - 若 max 仍随吹气大变化 → 按 §3.4 行 2 排查（接线未真正切换）
4. 对比两档：哪档 max 随声音变化 = 有效声道。

### 3.3 结论固化（记录到本 FEAT 维护章节）
- 有效声道：**左**（预期，待实验证实）/ 右
- 取数：v10 语义 = `extract_frame` 步进 4 取 `word[4k]` + `(int16_t)(raw & 0xFFFF)`（左声道模式实测标定，BUG-002 v10）
- 是否需要改代码：**否**（预期；两档都无数据或都有效 → 按 §3.4 排查后回阶段 3）

### 3.4 故障速查表
| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 两档 max 都恒 0 | 取数掩码错误 / SD 无输出 | 查 BUG-002；确认 SD 上拉；确认 A1-02 实际通过 |
| 两档 max 都随声音变 | 未真正切换 L/R（接线没换成功） | 断电重接，确认杜邦线接触 |
| 档位B 完全无数据 | 右声道本来无有效信号（正常现象） | 以档位A 为准，结论=左声道 |
| 吹气无反应 | 麦克风损坏 | 换模块（A1-01 §3.5） |
