## 2. P0 上电验收（S1~S5）

### 2.0 硬件前置（先查这三条，否则后面全是白忙）

| # | 项 | 判据 |
|---|---|---|
| H-1 | MPU6050 `VCC` → **3.3 V**（⛔ 不是 5 V） | 万用表量 VCC-GND = 3.3±0.1 V |
| H-2 | `AD0` → **GND**（悬空则地址可能变 0x69） | 量 AD0-GND 通断 |
| H-3 | `SCL`→**PF1**、`SDA`→**PF0**，且**有上拉**（GY-521 板载 4.7 kΩ 即可） | 断电量 SCL/SDA 对 VCC 电阻约 4.7 kΩ |

> ⚠️ GY-521 多数板子带 3.3 V LDO 与电平转换，**VCC 接 5 V 也能工作**，但本系统统一 3.3 V，避免与 I2C2 电平不匹配。

---

### S1 器件探测 + ID 校验

**操作**：烧录 → 看串口前 3 行。

| 期望输出 | 含义 |
|---|---|
| `[MPU] ok: WHO_AM_I=0x68  SMPLRT_DIV=15 (Fs=8k/16=500Hz) DLPF=0(260Hz) AFS=+-8g CLKSEL=PLL-Xgyro` | ✅ 通过 |
| `[MPU] no ACK at 0x68 (接线/供电/AD0?)` | 地址无应答 |
| `[MPU] WHO_AM_I=0xXX, expect 0x68` | 器件应答但不是 MPU6050 |
| `[MPU] I2C2 init fail st=n` | HAL 初始化失败 |

**失败分支处置**：

| 现象 | 最可能原因 | 下一步 |
|---|---|---|
| 无 ACK | SDA/SCL 接反 | 对调 PF0/PF1 再试 |
| 无 ACK | 无上拉 | 万用表量 SCL/SDA 对 3.3 V（应 ≈4.7 kΩ） |
| 无 ACK | 供电未到 | 量模块 VCC 脚 |
| 读到 `0xFF` | 总线被拉高无器件 / 地址错 | 试 0x69（AD0 悬空时） |
| 读到 `0x00` | 总线被拉低 / 短路 | 断电量 SDA-GND |
| ID = 0x70/0x72 等 | 不是 MPU6050（可能是 MPU6500/9250） | **停**，另查器件型号 |

---

### S2 采样率验证（本次最关键一步）

**为什么单列**：手册修正后 `SMPLRT_DIV=15` 是按 `Fs=8 kHz` 推的，**只有实采才能证实**。

**操作**：静止放置，看连续 5 行 `VIB,<rms>,<peak>,<N>` 的第 4 个字段。

| N（1 s 内实采样本数） | 判定 |
|---|---|
| **480 ~ 520** | ✅ 达标（500 Hz ±4%） |
| 400 ~ 480 | 🟡 可接受（任务被抢占约 10%），记录实际值 |
| **< 400** | 🔴 **不达标**，按下方分支处置 |

**失败分支**：

| 可能原因 | 验证方法 | 处置 |
|---|---|---|
| `vib` 任务被 Normal 任务饿死 | 看 N 是否随音频活动波动 | 优先级提一档，或把窗口改为 2 s |
| I2C2 时序不足（400 kHz 未生效） | 逻辑分析仪量 SCL 频率 | 降速到 100 kHz 重试 |
| `vTaskDelayUntil` 被 catch-up | 看 N 是否忽大忽小 | 改用固定采样数 + 时间戳自算 |
| **仍是 4 kHz 行为**（N 明显 >520 或数据重复） | 读回 `0x19` 确认真值 | **读回校验**：初始化后读 `0x19/0x1A/0x1C/0x6B` 并打印 |

> ⭐ **强制项**：S2 必须顺带做**寄存器读回校验**——`mpu6050_init()` 末增加"读回 4 个配置寄存器并打印"。写进去不等于生效，读回才作数。

### S3 零标定合理性

**操作**：上电后静止 2 s，看 `[MPU] calibrate done n=1000 zero=(x,y,z) LSB`。

**判据（关键）**：静止时合成重力模长应为 1 g = **4096 LSB**。

| 检查 | 通过线 |
|---|---|
| `sqrt(zx²+zy²+zz²)` | **4096 ± 10%（3686~4506）** |
| 其中一轴 \|零值\| | 接近 4096（重力落在该轴），另两轴接近 0 |
| `n` | ≥ 900（2 s × 500 Hz 的近满采样） |

**失败分支**：

| 现象 | 原因 | 处置 |
|---|---|---|
| 模长偏离 >10% | 标定时有振动/倾斜 | 静置重新上电 |
| 模长 ≈ 0 | 三轴都读到 0（总线错） | 回 S1 |
| 模长 ≈ 8192 | 量程不是 ±8 g（可能没写进去） | 读回 `0x1C` |

---

### S4 静态噪声底（基线的原料）

**操作**：静止 **10 min**，记录 600 个窗口的 `rms`。

| 指标 | 通过线 |
|---|---|
| `rms` 均值 μ | 记录（无绝对标准，看一致性） |
| `rms` 标准差 σ | **σ/μ < 0.3**（否则底噪不稳，基线不可用） |
| 削顶告警 | **0 次** |
| 掉线/重探 | **0 次** |

> ⚠️ 采集期间**不要碰桌子**；记录当时室温（SHT30 的 `temperature`），后续基线要标温度。

---

### S5 敲击响应（证明"能测到"）

**操作**：手指轻敲桌面 3 次（间隔 ≥2 s），每次看 1~2 个窗口。

| 判据 | 通过线 |
|---|---|
| `peak` 相对 S4 基线 | **上升 ≥ 5 倍** |
| `rms` 相对基线 | 上升 ≥ 1.5 倍（RMS 是均值，涨幅天然小于峰值） |
| 削顶告警 | 允许出现，但**若每次敲击都削顶** ⇒ 量程不足 |
| 恢复时间 | 敲击后 3 个窗口内回到基线 ±20% |

**量程不足的处置**：`0x1C` 改 `0x18`（±16 g，2048 LSB/g），同时 `LSB_PER_G` 改 2048.0f，`MG_PER_LSB` 自动跟随。

## 3. P1 基线采集

**采集条件（必须写进记录，否则基线不可复用）**：

```
安装：桌面平放 / MPU6050 与桌面刚性接触
环境：无人走动、无风扇直吹、无其他设备运转
时长：静止 10 min（600 个 1 s 窗口）
同步记录：室温（SHT30）
```

**产出三个数**：

| 量 | 计算 |
|---|---|
| `MU_RMS` | 600 个 `rms` 的均值 |
| `SIGMA_RMS` | 600 个 `rms` 的标准差 |
| `MU_PEAK` | 600 个 `peak` 的均值（峰值也是统计量，同样取均） |

**判据线**：

```
预警线 = MU_RMS + 2·SIGMA_RMS
报警线 = MU_RMS + 3·SIGMA_RMS
```

> ⚠️ 若 `SIGMA_RMS` 很小（如 < 5 mg），报警线会贴着实测值 ⇒ 任何扰动都触发。
> **对策**：加下限 `max(3σ, 0.2·μ)`，避免基线过窄导致的过敏。

## 4. P2 判据层（本地，不动 Modbus）

### 4.1 为什么不能写进寄存器

9 个寄存器**已满**（0~4 参数 + 5~8 遥测），`s2`/`level` 无处可放。扩到 10+ 要同时改从站、网关字典、云端物模型（A7-05 §4.3 已裁决：**本轮跨仓零改动**）。

⇒ **`s2` / `level` 只进串口与 OLED，不写 Modbus。**

### 4.2 实现要点

| 项 | 做法 |
|---|---|
| 异常度 | `s2 = min(100, 100·rms / ALARM_LINE)`（整数定点，避免浮点除法） |
| 三级 | `rms ≥ ALARM_LINE` → 2；`≥ WARN_LINE` → 1；否则 0 |
| 防抖 | 复用 `ROUND_BUF_N=6`（3 分钟 5 次）**不变**——每次只能动一个变量 |
| 串口格式 | 新增 `VIB2,<rms>,<peak>,<s2>,<level>`（**追加新行，不改 VIB 行**，避免破坏既有解析） |

### 4.3 验收

| 判据 | 通过线 |
|---|---|
| 静止 10 min | `level` 恒 0 |
| 敲击 | `level` 升到 ≥1，且 3 窗口内回落 |
| 与 `s1` 并列 | 两路互不阻塞（`vib` 任务不得阻塞 `specTask`） |

## 5. P3 融合与分诊（本地）

| 项 | 做法 |
|---|---|
| 融合 | `S = max(s1, s2)`；**共现升级**：若 `s1 ≥ 预警线` 且 `s2 ≥ 预警线` → 等级 +1（最高 2） |
| 分诊 | 主导通道 = 取 `s1`/`s2` 较大者；输出一句"振动主导 / 声学主导 / 两者同异常" |
| 只走本地 | 同样不写 Modbus（理由同 §4.1） |

**验收**：敲击（只有振动）→ 应报"振动主导"；拍手（只有声学）→ "声学主导"；两者同时 → 升级档。

## 6. P4 温度改角色

| 项 | 做法 | 边界 |
|---|---|---|
| 环境提示 | 环境温度 > 阈值或上升过快 → 单独一行提示 | **不计入设备报警** |
| 环境补偿（可选） | `k` 只作用于**本地判决的副本阈值**（`th_local = th × k`） | ⛔ **不写回从站寄存器**，不改 `th` |

> 为什么不能改 `th`：`th` 是从站参数，写它等于改全局行为；一旦补偿逻辑出错，会影响声学主判据。**本地副本**可以随时丢弃。

## 8. 风险与退路

| # | 风险 | 触发条件 | 退路 |
|---|---|---|---|
| R-A | 500 Hz 采样保不住 | S2 的 N < 400 | 降到 250 Hz（`SMPLRT_DIV=31`），论文口径改写 **10~90 Hz**（`DLPF_CFG=1`，184 Hz）——**不得含糊成 10~250 Hz** |
| R-B | 量程不足 | S5 每次敲击都削顶 | 改 ±16 g（`0x1C=0x18`，2048 LSB/g），同步改 `LSB_PER_G` |
| R-C | 基线不稳 | S4 的 σ/μ ≥ 0.3 | 延长到 30 min；或改判据为"分位数"（p99）而非 μ+3σ |
| R-D | 与音频任务抢 CPU | N 随音频活动明显下降 | `vib` 优先级提一档（仍低于 `specTask`） |
| R-E | 削顶被误当"高振动" | 只看 rms 不看 clip | **强制**：任何含 clip 的窗口，`level` 不得高于 1（降级处理） |
