## 1. 总体目标与方向

### 1.1 核心目标（一句话）
> 用 **Python（Anaconda 3.13.5）+ matplotlib + tkinter + pySerial** 做 PC 端上位机，统一整合现有计划中的 PC 端需求：频谱实时显示、模版采集训练、参数下发、报警监控，通过 **RS485（对接 A5）** 与板子通信。GUI 不引入 PySide6（6.11 DLL 加载失败已放弃，事实包 §3.7）。

### 1.2 大方向策略
> 先做**通信层**（A8-01，对接 A5-02 帧协议）打通数据管道；再做**频谱显示**（A8-02，对接 A2-04 输出）——这两步是基础；模版训练（A8-03）与参数/报警（A8-04）依赖前者。A8-03 的 K-means 与 A4-01 是同一算法，PC 端实现可提前独立开发（只需数据文件，不依赖硬件）。GUI 用 tkinter + matplotlib（Anaconda 自带，零安装）。

### 1.3 硬边界（继承 CLAUDE.md）
- [x] 是否涉及底层库 / 第三方库？→ 否（PC 端应用，不碰 `firmware/Drivers/`；第三方库 PySide6/pySerial/numpy 经 pip 安装，不改其源码）
- [x] 否 → 继续

### 1.4 关键参数与接口（事实包 §3，禁止自造）
- **语言/框架**：Python 3.13.5（Anaconda）+ **tkinter + matplotlib 3.10.0**（GUI，自带）+ pySerial（已装）+ numpy（自带）+ scikit-learn 1.6.1（K-means，自带）。
- **通信链路**：PC 端 USB-TTL(CH340) → TTL-RS485 模块(3.3V/SP3485，引脚 EN/VCC/A/B/GND×2/RXD/TXD) → A/B 对接 → 板端模块 → USART3（PD8/PD9，115200，EN=PD11）——见 A5-01/A5-03。
- **帧协议**：对接 A5-02（帧头 0xA5 / 帧尾 0x5A / CRC16；参数未定，需人确认）。
- **频谱数据**：对接 A2-04 输出（一行 32 个整数，~200ms 节流）。
- **模版**：13 维 MFCC × K=16（A4-01 约定），训练数据来自板端串口采集。
- **参数下发**：阈值/帧数（A4-04 约定，30/60 帧基线）。
- **待定（需人确认）**：绘图库选型、Python 版本、打包分发方式（pyinstaller？）、日志格式、模版文件格式。
