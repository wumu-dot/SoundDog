## 1. 总体目标与硬边界

### 1.1 核心目标（一句话）
> 使能 IWDG 独立看门狗：系统异常死机（任务/主流程卡死）时**自动复位**，复位后串口重新输出 boot 三行可观测。

### 1.2 地基触碰前置自检
- [x] 否 → 继续（经 HAL IWDG 标准接口使能/喂狗，不触碰 `firmware/Drivers/` 底层库文件）

### 1.3 任务边界
| 类型 | 具体内容 |
|------|----------|
| 范围内（可改） | 新建/挂接喂狗任务（App 层）、`soundDog.ioc` 使能 IWDG、模拟死机测试点（条件编译） |
| 超出范围（禁止碰） | `firmware/Drivers/` HAL 底层库文件 |
| 外部依赖 | 无新增硬件（复用现有核心板） |

### 1.4 关键参数（事实包 §3，禁止自造）
- IWDG 超时时间 / 预分频 / 重装载值：**待定（需人确认）**。
- 喂狗函数：`HAL_IWDG_Refresh`（HAL 标准接口，**禁止修改 HAL**）。
- 🚫 **硬性红线（FreeRTOS 配合）**：
  - **喂狗只能在任务上下文（独立喂狗任务）中调用，禁止在任何中断服务函数（ISR）里喂**——中断仍运行时主流程可能已死，ISR 喂狗会掩盖死机，使看门狗失去意义。
  - 中断优先级 0~4 禁止调用 FreeRTOS FromISR API（CLAUDE.md 铁律）；喂狗走任务路径，不涉及 FromISR。
  - 喂狗任务堆栈 ≥ 256 字（CLAUDE.md：业务任务最低 256 字）；喂狗周期必须 < IWDG 超时（**具体周期/优先级待定需人确认**）。
- 复位观测：复位后串口重新输出 `SoundDog boot OK` → `I2S_DRV_Init ret=0` → `I2S DMA started`（事实包 §3.4）。
- 调试注意：IWDG 一旦使能无法在运行中关闭，**调试暂停（halt）时看门狗仍计数可能触发复位**；调试构建关闭 IWDG 的条件编译开关：**待定（需人确认）**。
- 复位原因区分（IWDG 复位 vs 上电复位）：**待定（需人确认，如读取复位标志）**。

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 频繁意外复位 | 喂狗周期 ≥ 超时 / 喂狗任务被饿死（优先级过低长期被抢占） | 缩短喂狗周期；调高喂狗任务优先级或改由空闲钩子喂（需人确认） |
| 模拟死机后不复位 | IWDG 未使能 / 超时过长 / 测试点未编译进去 | 查 ioc 使能与超时（待定）；确认条件编译开关生效 |
