# SoundDog RS485 链路重测记录（2026-09-21 晚）

> 本文档只记录当晚执行的动作与观测事实，不写结论。结论归属后续处置环节。

## 1. 当晚执行的动作序列

1. 固件以 `-DMB_PROBE_ENABLE=0` 重新编译并烧录（探针关闭版）。
2. 逻辑分析仪接线：
   - CH0 = MAX3485 模块 A 端子
   - CH1 = USB转RS485 适配器 485A 端子
   - CH2 = STM32 PD8（USART3_TX）
   - CH3 = STM32 PD9（USART3_RX）
   - GND = 板子 GND
3. PC 经适配器（COM5）发送问询帧 `01 03 00 00 00 01 84 0A` @115200。
4. 发送后 PC 端读回为空（无任何字节）。
5. 对问询帧做 CRC16-Modbus 校验：`01 03 00 00 00 01` 的 CRC = `0x0A84`，低字节在前 = `84 0A`，与发送帧尾一致。

## 2. 逻辑分析仪观测事实

| 通道 | 测点 | 观测 |
|---|---|---|
| CH0 | 模块 A 端子 | 有 UART 波形；解码显示为 `130001` + `132` + 换行 |
| CH1 | 适配器 485A 端子 | 有 UART 波形（与 CH0 同源） |
| CH2 | PD8（USART3_TX） | 无波形（两次：短窗口 0.9ms；拉长至 200ms~1s 窗口） |
| CH3 | PD9（USART3_RX） | 无波形（两次独立抓取，第二次为重测） |

### CH0 解码显示 `130001` 是什么（事实拆解）

CH0 抓到的字节按**十进制数值**解码，与问询帧逐字节对应：

| 问询帧字节 | 十进制 | 解码显示 |
|---|---|---|
| 0x01 | 1 | `1` |
| 0x03 | 3 | `3` |
| 0x00 | 0 | `0` |
| 0x00 | 0 | `0` |
| 0x00 | 0 | `0` |
| 0x01 | 1 | `1` |
| 0x84 | 132 | `132` |
| 0x0A | 10 | 换行 |

即 `130001` + `132` + 换行 = 问询帧 `01 03 00 00 00 01 84 0A` 本身。
CH0 观测到的就是适配器发出的问询帧字节流（以十进制文本显示），说明问询帧出现在了模块 A 端子上。

## 3. 固件代码核对事实（只读，当晚未改代码）

- `usart.c`：USART3 引脚 PD8=TX / PD9=RX（AF7）；PD11 输出推挽，初始写低；USART3_IRQn 优先级 5 并使能。
- `rs485_drv.c`：`RS485_Init()` 将 EN(PD11) 置低（接收态）；`RS485_Send()` 先置高（发送）→ 阻塞发送 → 等 TC → 回低。
- `pin_config.h`：RS485_TX=PD8、RS485_RX=PD9、RS485_DE=PD11。

## 4. 更早已记录的观测事实（供对照，非当晚）

- 探针开启版（`MB_PROBE_ENABLE=1`）下，TTL 直灌 PD9 时，PD8 曾抓到应答帧 `01 03 02 02 58 B8 DE`。
- MAX3485 RO 引脚（丝印 RX）对地静态电压 0.15V（9-17 记录，R48/R49）。
- 适配器裸端差分 1.8~2.3V（110 波特率测量，R50 记录）。
