## 一、RS485 丝印三条（历史错过两次，最高优先级）

### 1. `RS485.SILK_DIR` —— 模块丝印的方向语义

| 项 | 内容 |
|---|---|
| **事实** | 模块丝印 `TXD` = 模块**发送**端（≈DI），接 MCU 的 **TX**；`RXD` = 模块**接收**端（≈RO），接 MCU 的 **RX** |
| **板型** | 板面印 `RS485` / `V2.0`；左列 `EN / VCC / RXD / TXD / GND`，右列 `GND / A / B`（两列**不对称**） |
| **出处** | `docs/hardware/硬件配置-2026-09-16.md` §2、§3 |
| **版本 / 核实** | 2026-09-16 用户实物确认；2026-11-26 复核 |
| **代码落点** | 无（纯接线事实） |
| 🔴 **易错点** | 丝印是**模块自身视角**，不是 MCU 视角。凭"MCU 的 TX 应该接 RXD"的直觉接线 = 接反。 |

**新接法（2026-10-25 起，直连）**：

| STM32 | → 模块丝印 | 芯片功能 |
|---|---|---|
| `PD8`（USART3_TX, AF7） | → **`TXD`** | ≈DI |
| `PD9`（USART3_RX, AF7） | ← **`RXD`** | ≈RO |
| `PD11` | → `EN` | ≈DE/RE（高发/低收） |
| VCC | → `VCC` | **3.3 V**，⛔ 不是 5 V |

---

### 2. `RS485.SIDE_CONVENTION` —— 两侧模块约定是否一致

| 项 | 内容 |
|---|---|
| **事实** | **2026-10-25 起统一**：从站 `RS1` 换成与网关 `RS2` 同款 ⇒ **两侧都是直连**（`TX→TXD`、`RX→RXD`） |
| **变更前** | `RS1` 与 `RS2` 是**不同厂家**，TTL 丝印约定相反 ⇒ `RS1` 要**交叉**（`PD8→RXD`、`PD9←TXD`） |
| **出处** | 同上 §2（R42） |
| **版本 / 核实** | 2026-10-25 换模块；2026-11-26 复核 |
| 🔴 **易错点** | **同一个「TXD→PD8」在旧模块是错的、在新模块是对的。** ⛔ 只看引脚名 → 必错；必须看**模块型号**。 |
| ⚠️ **作废文档** | `桌面\报告\目前进度\souddog\SoundDog-RS485链路排查测试-2026-09-17.md` §2 的接线表**整篇作废**，严禁引用 |

---

### 3. `RS485.AB_ORDER` —— 差分 A/B 对应与判据

| 项 | 内容 |
|---|---|
| **事实** | `A` = 差分正（485A / A+）→ 接对端 `A`；`B` = 差分负（485B / B−）→ 接对端 `B` |
| **空闲判据（原文有）** | A、B 对 GND 应有**明显压差**且 `A−B ≠ 0`；**`A≈B≈1.67 V` = 漂浮电平 ⇒ 共地缺失** |
| **出处** | 同上 §3、§4 |
| **版本 / 核实** | 2026-09-28 实物核对；2026-11-26 复核 |
| 🔴 **原文没有的（不得写成事实）** | **「如何判定 A/B 反相」的方法，存档里没有记载。** 当时的实证方式是**位流模拟**（2026-10-26 20:5x），属推断而非手册规定。 |
| ⛔ **禁止的自检法** | 不得用「B 碰 5 V」法（R36/R37 烧板前科：5 V 倒灌击穿 3.3 V 轨） |

> ⚠️ 本条同时是「表里只放事实、不放推断」的示范：**漂浮判据是文档写的，反相判定是推断**，两者必须分开写。

## 二、MPU6050 采样率两条（今天刚错，且错得隐蔽）

> ⚠️ **本机未存档 MPU6050 手册**。以下依据为线上 PDF（InvenSense 原文 Rev 4.2 / dfrobot 镜像 Rev 4.0）。
> ⇒ **缺口**：无法离线复核。建议把 PDF 存入 `docs/hardware/datasheets/`（待办）。

### 4. `MPU6050.SR_FORMULA` —— 采样率公式

| 项 | 内容 |
|---|---|
| **事实** | `Sample Rate = Gyroscope Output Rate / (1 + SMPLRT_DIV)` |
| **出处** | RM-MPU-6000A **Rev 4.0 §4.2**（Register 25 – Sample Rate Divider） |
| **核实** | 2026-11-26 |
| **代码落点** | `BSP/mpu6050.c:REG_SMPLRT_DIV_VAL` |
| 🔴 **易错点** | 公式看着简单，但分母的 `Gyro Output Rate` **不是常数**（见下一条）。**只记住公式 = 会算错。** |

### 5. `MPU6050.FS_BASE` —— 公式的基准随配置变

| 项 | 内容 |
|---|---|
| **事实** | `Gyro Output Rate = 8 kHz` 当 `DLPF_CFG = 0` 或 `7`；`= 1 kHz` 当 `DLPF_CFG = 1~6` |
| **附加事实** | 加速度计输出率恒为 **1 kHz**；当 Sample Rate > 1 kHz 时，**同一 accel 样本会被重复输出** |
| **出处** | 同上 **§4.2 正文 + §4.3（Register 26 表 `Fs (kHz)` 列）** |
| **核实** | 2026-11-26 |
| **代码落点** | `BSP/mpu6050.c` 的 `REG_CONFIG_VAL=0x00`（⇒ 8 kHz 基准）+ `REG_SMPLRT_DIV_VAL=0x0F`（⇒ 8000/16 = 500 Hz） |
| 🔴 **这就是今天错误的根源** | 我按 **1 kHz** 基准推算 `SMPLRT_DIV=1 ⇒ 500 Hz`，实际 `DLPF_CFG=0 ⇒ 8 kHz` ⇒ 得 **4000 Hz**，且每 4 个读数 3 个重复 ⇒ **RMS/峰值系统性低估** |
