## 0. 为什么要重构（不是"看起来乱"）

实测数据，非观感：

| 指标 | 值 | 说明 |
|---|---:|---|
| `.claude/rules.md` | **24,873 B** | 每次会话**全量注入** |
| 节数 | 8（§0~§7） | §7 是"登记表"，不是条文 |
| §7 体量 | **2,621 B** | 占 10.5%，但只在**查证时**需要 |
| 规则号 | R0~R32 全文 + **R33~R43 仅索引** | 编号完整，无跳号 |
| `CLAUDE.md` | 6,577 B | 含一行 `DOC-STATE` |
| pre-commit | 2 个 PowerShell（R19/R27） | 只覆盖 **2/43 ≈ 5%** |
| `scripts/` | 24 个 | 含 `check-doc-drift.sh`、`ci_local.sh` |

### 三个真问题

| # | 问题 | 证据 |
|---|---|---|
| **1** | **§7 登记表混在规则正本里** | 2,621 B 的索引表每次会话都被读，但只有"查某条 R3x 在哪定义"时才用 ⇒ 纯注入开销 |
| **2** | **§7 的"权威定义位置"从未被校验** | 抽查索引列 → `MAX3485-RS485模块资料/README.md` **路径不存在**（≥1 处悬空）。这与 em 的 R2 同类：写了引用，没人验 |
| **3** | **DOC-STATE 只走 ci_local，不在提交时拦** | `check-doc-drift.sh` 存在且被 `ci_local.sh` 调用，但 **pre-commit 不跑 ci_local** ⇒ 只有"主动跑 CI"才校验 |

## 1. 目标（可判定的三条）

| # | 目标 | 判据 |
|---|---|---|
| G1 | 正本瘦身 | `.claude/rules.md` **≤ 20 KB**，且 §7 移出 |
| G2 | 悬空引用清零 | 规则里出现的**所有文件路径/节号/规则号**都能 `test -e` / `grep` 命中 |
| G3 | 提交时强制 | pre-commit 至少覆盖 **≥3 条**可机器验证的规则（现 2 条） |

**明确不做**：不重写 R0~R32 条文、不改编号、不合并 FEAT 文档、不动代码。

## 2. 方案（三阶段，每阶段可独立回滚）

### P0 外置 §7 登记表（预计 30 分钟）

| 动作 | 细节 |
|---|---|
| 建 `docs/summary/rule-index.md` | 把 §7 整节（表格）原样搬过去，**不改一个字** |
| 正本留指针 | `## §7 规则索引（R33~R43）` → 一句话 + 链接 |
| 校验 | 正本 ≤20 KB；`docs/summary/rule-index.md` 存在且含 R33~R43 全部 11 行 |

**回滚**：`git revert`，无副作用（纯移动）。

### P1 建"引用校验"（预计 1 小时）

| 动作 | 细节 |
|---|---|
| 写 `scripts/check_rule_refs.py` | 抽规则里的 `路径.md/.sh/.ps1`、`§N`、`R(\d+)`，逐个验证；**匹配串必须从原文复制**（em 那次踩过：凭印象写 `firmware/Core` 而原文是 `Core/`） |
| 先只报 WARN | **零误报**再升级 FAIL——误报一次就会被 `--no-verify` 绕过 |
| 修掉已发现的悬空 | `MAX3485-RS485模块资料/README.md`：补文件 / 改指向 / 删条目，三选一 |

**验收**：`python scripts/check_rule_refs.py` 输出 **0 项**。

### P2 把校验挂进 pre-commit（预计 30 分钟）

现有钩子：

```sh
powershell -File scripts/check_r19_zone.ps1  || exit 1
powershell -File scripts/check_r27_research.ps1 || exit 1
```

| 动作 | 细节 |
|---|---|
| 追加两项 | `check_rule_refs.py`（P1 产物）+ `check-doc-drift.sh`（已存在，只需接线） |
| 只对 staged 生效 | 避免每次提交跑全库（实测 Python 检查器约 740 ms，PowerShell 约 360 ms/个 ⇒ 串起来约 1.5 s，可接受） |

**回滚**：钩子不在版本库，删 `.git/hooks/pre-commit` 即恢复。

## 3. 风险与止损

| 风险 | 后果 | 止损 |
|---|---|---|
| 移动 §7 时内容丢失 | 索引信息断 | 搬迁后 `diff` 校验：新旧表格行数、R33~R43 逐号比对 |
| 新校验器误报 | 被 `--no-verify` 绕过，全盘失效 | **先 WARN，零误报两周后再 FAIL** |
| 提交变慢 | 摩擦 | 只对 staged；实测 ≤2 s |
| 有人同时改 rules.md | 冲突 | 三个阶段分开提交，每次一个 commit |
